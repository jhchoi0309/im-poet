# 평가 방법과 검증 범위

## 2026-11-22 개정 0.8.2

README의 전후 비교 여덟 쌍은 2026년 11월 18일에 0.8.0 지침으로 다룬 시험 에세이에서 골랐다. 0.8.2는 예문의 배경을 설명하고, 설치와 데이터 처리의 범위와 대표 문헌을 문서에서 확인할 수 있게 했다. 이번 검사는 지침에서 만든 프롬프트, 문서 링크, 설치 과정과 보조 도구를 대상으로 했다. 읽기 예시는 지난 작업의 발췌로 표시했다. [0.8.1에 반영한 에세이 평가](feedback-0.8.1.md), [0.8.2 실행 기록](compatibility.md)

## 2026-11-18 개정 0.8.1

[첨부 평가에 반영한 변경](feedback-0.8.1.md)은 독서부터 인공지능까지 가상 에세이 여섯 편에서 드러난 문제를 다룬다. 이번 작은 비교에는 그 문장들을 사용하지 않았다. 별도로 만든 수선집 수필, 독서실 운영 논설, 현관에서의 손짓이 반복되는 단편을 같은 요청 아래 기본 윤문, 0.8.0 지침, 0.8.1 지침에 한 번씩 입력했다. 두 개정의 독립 프롬프트를 사용했으며 작성자에게 기대 답이나 순위를 건네지 않았다.

| 사례 | 버전을 모르는 보조 평가자의 판단 |
| --- | --- |
| 수선집 수필 | 0.8.1 선호. 가방 안을 들여다보는 행동이 글의 앞뒤를 붙들었고, 친구의 다른 선택과 비용에 관한 반론도 남았다. '더'가 화자의 수선 전 사용을 암시할 여지는 있었다. |
| 독서실 운영 논설 | 0.8.0과 일반 윤문이 동률로 우세. 0.8.1도 가능성과 공개 의무를 지켰으나, 이용 기회를 먼저 배치하여 기록과 근거를 확인하는 흐름이 약해졌다. |
| 현관의 손짓 | 0.8.1 선호. 주머니의 짧은 반복과 시작과 끝의 박자가 손을 내미는 사람이 바뀌는 순간을 살렸다. 마지막 행동의 뜻은 확정하지 않았다. |

이 평가에서는 중대한 의미 손실과 추가는 기록되지 않았고 작은 말의 변화는 별도로 남겼다. 가상 원고 세 편과 AI 평가 1회이며, 정확한 백엔드 모델 식별자와 생성 설정은 확인할 수 없었다. 사람의 평가나 여러 모델과 반복 실행은 아직 수행하지 않았다. [실제 아홉 출력과 평가](../evals/results/release-0.8.1.json)를 보존한다.

Linux에서 Codex, Claude Code, Gemini CLI의 설치 명령과 백업 없는 교체를 실행했다. 기계 테스트와 발견 범위, 0.8.0의 공개 CI와 새 버전의 차이는 [호환성](compatibility.md)에서 확인한다. 이 결과를 문학적 선호와 합산하지 않는다.

## 2026-11-17 개정 0.8.0

기존 0.7.0의 전면 재서술을 유지하며 수정의 역할과 반례, 관점과 담화, 독립적인 검수 기준을 보강했다. 현재 내부 문서와 독립 프롬프트, 연구 목록과 설치 안내를 갱신했다. 다음 이전 버전 기록은 당시의 결과로 보존하며 새 버전의 성과로 합산하지 않는다.

개발 비교는 회고 산문, 기술 기록, 일인칭 소설의 세 원고를 대상으로 했다. 이전 0.7.0과 초기 0.8.0의 별도 에이전트 세션에 같은 요청과 원문을 전달해 여섯 출력을 얻었다. 다른 에이전트 한 번이 버전과 작성자를 가린 X와 Y를 읽었다. 기대 답은 작성 단계에 전달하지 않았다. 정확한 백엔드 모델 ID는 노출되지 않아 확인하지 못했다.

그 보조 평가자는 회고 산문에서 0.8.0, 소설에서 0.7.0을 선호했고 기술 기록은 동률로 판단했다. 확인된 의미 문제를 적지 않았으나 이는 인간의 독립 검수가 아니다. 세 원고와 한 판정, 각 한 번의 출력으로 일반적인 개선을 주장하지 않는다. 기술 기록의 조건은 기존 개발 예문과 유사하므로 봉인된 독립 시험으로도 세지 않는다.

이 비교 후에는 의미 보존과 문학적 선호를 혼동하지 않고 결과를 그대로 남겼다. 평가 결과를 보고 유리한 출력만 고르거나 기존 출력을 재작성해 비교 수치를 교체하지 않았다. 원문과 실제 출력, 익명화 순서와 평가 이유는 [릴리스 검증 자료](../evals/results/release-0.8.0.json)에 담는다.

설치에서는 세 CLI의 경로, 백업 없는 교체와 복구, 사용자 지정 설정, Gemini 공용 별칭과 보조 도구를 점검했다. 네이티브 운영체제의 실행 범위는 [호환성](compatibility.md)에 구분한다. 현재 호스트의 Codex 발견 검사는 읽기 전용 상태 경로에서 초기화 중단을 관찰했으며, 이를 지침의 발견 성공으로 표시하지 않는다. Claude 계정 세션의 발견과 세 제공자의 로그인 후 모델 생성은 실행하지 않았다.

기계 검사의 최종 개수와 생략, 네이티브 검사 보고서는 연결된 JSON의 실제 실행 결과를 따른다. 아홉 CI 작업의 정의와 현재 릴리스의 네이티브 통과 기록은 서로 다르다. 연구의 판독 범위는 [연구 문서](research.md)에 남겼다.

## 형식, 도구 검사와 문장 평가의 구분

자동 검사로 설치 경로와 백업, 복구를 확인한다. 패키지와 독립 프롬프트의 지침이 같은지도 대조한다. 윤문을 읽을 때는 원고와 결과를 나란히 놓고 뜻이 남았는지부터 살핀다. 이어 어휘와 호흡, 문단의 흐름이 어떻게 달라졌는지 읽는다.

```bash
python3 scripts/build.py --check
python3 scripts/check.py
python3 -m unittest discover -s tests -v
```

## 2026-11-16 문체와 검수 개정 0.7.0

일곱 공개 프로젝트의 실제 안내와 핵심 지침을 읽고 문체 샘플의 분석, 작업 범위의 구분, 은유와 호흡의 판단, 과잉 윤문 검수를 선별했다. 외부 스킬을 설치하거나 실행하지 않았으며 특정 저자의 원문과 문체 분석 자료, 예문은 복제하지 않았다. [설계 비교와 제외한 요소](../references/project-comparison-0.7.0.md)에 확인 범위를 기록했다. 기존 작품 140편과 논문 74편의 조사 기록은 2026-11-14 자료이며 이번 비교의 새로운 독해 수치로 세지 않는다.

0.6.2와 첫 0.7.0 후보에는 문체 샘플, 서사 산문, 기술 기록의 같은 세 요청을 각각 한 번씩 전달했다. 이후 후보의 미완성 종결과 기술 기록의 불필요한 대비를 검수하도록 보강하고 다섯 요청을 실행했다. 이 다섯 건에는 검토만 하는 요청과 가벼운 교정도 포함했다. 마지막으로 결말의 의미 중복을 살피는 규칙과 별도 예문을 더한 최종 지침으로 서사 요청 한 건을 다시 실행했다. 작성자들은 이전 대화를 물려받지 않았고 원문과 요청, 적용할 지침만 받았다. 기대 답안과 평가 기준은 주지 않았다.

[실제 요청과 원문, 열두 출력, 단계별 지침 지문과 별도 대조](../evals/results/forward-0.7.0-2026-11-16.json)를 함께 남겼다. 첫 여섯 출력, 후속 다섯 출력, 마지막 한 출력의 지침은 서로 구별한다. 마지막 지침으로 모든 사례를 다시 실행한 것은 아니다. 모델의 정확한 식별자와 샘플링 설정은 노출되지 않아 확인하지 못했다.

| 확인한 대목 | 발견한 문제와 반영 | 후속 결과 |
| --- | --- | --- |
| 샘플을 참고한 문체 | 샘플의 평이함과 짧은 종결을 화려함에 가리지 않도록 현재 요청과 적용 가능한 특성을 먼저 읽게 했다. | 샘플의 소재를 옮기지 않고 두 책의 상태와 반납일, 설명하기 어려운 이유와 존대를 지켰다. 두 번째 익명 비교에서는 동률이었다. |
| 서사 산문의 결말 | 첫 후보의 미완성 구절, 다음 후보의 같은 인식을 되풀이하는 세 구절을 발견했다. 문법적 연결과 각 구절이 더하는 뜻을 따로 읽도록 했다. | 최종 재시험에서는 인식을 밝히고 길목의 이미지로 받는 두 문장으로 정리됐다. 주 작업자가 의미를 대조했으며 이 마지막 출력의 별도 익명 선호 평가는 수행하지 않았다. |
| 기술 기록 | 원문에 없는 수사적 대비가 남았다. 정확한 기록을 다시 장식하는 해설과 실제 반론을 구별하게 했다. | 후속 출력에서 해당 대비가 사라졌다. 팀의 측정과 개인의 정리, 수치와 순서, 미확인 원인과 재실험 미실시, 일정과 의무를 대조했다. |
| 검토만 하는 요청 | 기본 전면 재서술이 피드백 요청까지 넓어지지 않는지 살폈다. | 모호함을 진단하고 전문을 다시 쓰지 않았다. |
| 가벼운 교정 | 의도한 반복과 지정한 마지막 문장을 지켜야 했다. | 한 표현만 줄이고 기다림의 반복과 마지막 문장을 남겼다. |

버전 대응을 숨긴 비교에는 별도 문맥의 모델 평가자 두 명을 사용했다. 첫 비교에서는 0.6.2를 세 건 모두 근소하게 선호했고, 보강 뒤 두 번째 비교에서는 두 건을 동률로, 서사 한 건을 0.6.2 근소 우세로 판단했다. 이 의견에서 드러난 문제를 다음 수정에 반영했다. 명백한 사실 오류는 두 평가자 모두 발견하지 못했지만 이는 완전한 의미 일치의 보증이 아니다. 사람의 선호 평가와 반복 실험을 수행하지 않았으며 작은 표본으로 새 버전의 우월성을 주장하지 않는다.

Linux의 Python 3.12.14에서 자동 테스트 68개 중 66개가 통과했고 네이티브 Windows junction과 PowerShell 검사 두 개는 건너뛰었다. 새 읽기 전용 비교 도구의 테스트 여덟 개를 포함한다. 원문과 결과를 읽을 때 본문을 유출하거나 수정하지 않는지, 잘못된 설정과 누락된 보호 구절, 금지 문자에 맞는 종료 코드를 내는지 확인했다. 부정이 뒤집힌 문장도 선택한 문자열 검사만 통과할 수 있음을 테스트로 남겼다. 도구는 이를 의미 일치로 판정하지 않고 수동 검수를 요구한다.

현재 Linux의 Codex CLI 0.167.0-alpha.4로 임시 프로젝트의 발견 검사를 시도했으나 스킬 목록 요청 전에 실행 환경의 상태 데이터베이스를 열지 못하고 종료됐다. 이 실행을 0.7.0의 발견 성공으로 세지 않는다. 이전 버전의 세 운영체제 CI 기록과 이번 검사는 날짜와 범위를 구분한다. macOS와 Windows의 네이티브 실행, Claude와 Gemini 모델의 인증 후 윤문, 음성 낭독과 실제 조판은 이번 환경에서 실행하지 않았다.

## 2026-11-14 개정본 0.6.0 직접 점검

현재 Codex 대화의 작성자가 0.6.0 지침과 작업 맥락을 읽은 상태에서 12개 사례의 답안을 한 번씩 직접 작성하고 의미와 문체를 대조했다. 별도의 모델 호출이나 격리된 새 대화가 아니며 평가자도 같은 작성자다. [원문, 요청, 실제 작성 결과, 사례별 검토](../evals/results/manual-0.6.0-2026-11-14.json)를 모두 남겼다.

과거 0.5.0 최종본에서 실제 실행한 E1과 E5에는 같은 원문과 요청을 사용했다. E3의 이전 결과는 최종본이 아닌 후보 A다. 날짜와 맥락이 다르고 모델 식별자와 샘플링 설정의 일치도 확인되지 않아 통제 비교가 아니다. 이 결과로 0.6.0이 더 우수하다고 단정하지 않는다.

첫 결과에서 N01과 N07은 문장 연결이 없던 동시성을 암시할 여지가 있었고, N03은 불필요한 대비, N06은 중복 표현이 남았다. 접속 관계와 수정 뒤 중복을 확인하도록 지침을 보강한 뒤 같은 작성자가 네 사례를 다시 썼다. 이미 답안과 문제를 본 상태의 수정이므로 독립 재시험이나 지침 변경의 인과적 효과는 아니다. N02와 N07에서는 정확성을 유지해도 문학적 변화가 약했다.

보호된 원문과 금지 문자가 충돌하는 N04에서는 해당 구절을 변조하지 않고 출력을 보류했다. N05의 원고 속 명령은 작업 지시로 실행하지 않았다. 문학성, 자연스러움과 저자 선호는 별도 독자와 반복 평가가 필요하다. 각 사례는 한 번의 출력이므로 실패율이나 성공률로 일반화하지 않는다.
